## 需求背景

实现一个跨链桥服务，支持 Arbitrum 与本地链之间的 USDC 双向转账。该服务需要实现经典的 Lock-Mint-Burn-Release 机制，确保资产在两条链之间安全、可靠地转移。

业务目标：
- 用户可以在 Arbitrum 上锁定 USDC，并在本地链上获得等量的映射 USDC
- 用户可以在本地链上销毁映射 USDC，并在 Arbitrum 上解锁原生 USDC
- 保证跨链转账的一致性和安全性，防止双花和重放攻击
- 提供可验证的转账日志和演示脚本

触发场景：
- 用户需要在不同链之间转移 USDC 资产
- DeFi 应用需要跨链流动性支持

## 现有的代码情况（包括与需求相关的代码功能实现和可用接口）

当前仓库为全新项目，`docs/` 目录外无任何代码实现。

**重要架构说明**：
- Arbitrum 是 **EVM 链**，使用 Solidity 编写智能合约
- 本地链是 **Solana 链**，使用 Anchor 框架（Rust）编写程序
- 这是一个 **EVM ↔ Solana** 异构链跨链桥

**测试环境说明**：
- **EVM 侧**：使用 Hardhat 本地 ETH 测试链（代替 Arbitrum 测试网）
- **Solana 侧**：使用 solana-test-validator 本地测试验证器（代替 Solana 主网/测试网）
- **USDC 代币**：在 EVM 侧使用标准 ERC20 代币合约（代替真实 USDC）；在 Solana 侧使用 SPL Token
- 测试环境可完全在本地运行，无需连接外部测试网

需要从零开始创建以下模块：

1. **contracts/evm/** - EVM 侧 Solidity 合约
   - 需要实现 EVMBridge.sol（锁定和释放功能）
   - 需要实现 MockUSDC.sol（模拟 ERC20 USDC 代币，用于测试）
   - 使用 Hardhat 进行开发和测试
   
2. **programs/local-bridge/** - Solana 侧 Anchor 程序
   - 需要实现 local_bridge Anchor program（铸造和销毁功能）
   - 需要集成 SPL Token 作为桥接 USDC（在测试环境中创建）
   - 需要实现 PDA（Program Derived Address）管理
   - 使用 Anchor 框架进行开发和测试
   
3. **relayer/** - 跨链中继服务模块
   - 需要实现 EVM 事件监听（ethers.js，连接到 Hardhat 本地节点）
   - 需要实现 Solana 事件监听（@solana/web3.js，连接到 solana-test-validator）
   - 需要实现跨链交易执行逻辑（处理两种不同的交易格式）
   - 需要实现 nonce 管理和防重放机制

4. **scripts/** - 部署和演示脚本
   - 启动本地测试环境脚本（Hardhat 和 solana-test-validator）
   - 部署合约和初始化脚本
   - CLI 演示脚本

目前无可重用接口，所有功能需要全新开发。

## 需求实现预期结果及验收标准

### 功能验收标准

**1. 智能合约部署验收**
- Hardhat 本地 ETH 测试链上成功部署 EVMBridge 合约和 MockUSDC 合约，合约地址可查询
- solana-test-validator 上成功部署 local_bridge Anchor 程序
- Solana 侧成功创建 SPL Token（桥接 USDC）
- 两个链的合约能够正确配置对方链的信息（Relayer 地址、代币地址等）

**2. Lock → Mint 流程验收**（EVM → Solana）
- 用户在 Hardhat 本地链上调用 EVMBridge 的 lock 函数，锁定指定数量的 MockUSDC
- 合约正确发出 `Locked` 事件，包含字段：用户 EVM 地址、Solana 接收地址、金额、nonce
- Relayer 监听到 `Locked` 事件
- Relayer 在 Solana 测试验证器上调用 local_bridge 的 mint 指令，为用户铸造等量 SPL Token
- Solana 程序发出 `Minted` 事件（通过 Anchor Event）
- 用户在 Solana 上的 SPL Token 余额增加对应数量

**3. Burn → Release 流程验收**（Solana → EVM）
- 用户在 Solana 测试验证器上调用 local_bridge 的 burn 指令，销毁指定数量的 SPL Token
- 程序正确发出 `Burned` 事件，包含字段：用户 Solana 地址、EVM 接收地址、金额、nonce
- Relayer 监听到 `Burned` 事件
- Relayer 在 Hardhat 本地链上调用 EVMBridge 的 release 函数，为用户解锁等量 MockUSDC
- EVM 合约发出 `Released` 事件
- 用户在 Hardhat 本地链上的 MockUSDC 余额增加对应数量

**4. 安全机制验收**
- **Nonce 机制**：每笔跨链交易具有唯一递增的 nonce，已处理的 nonce 不能重复使用
- **防重放**：尝试使用相同 nonce 提交交易时，合约应拒绝并抛出错误
- **幂等性**：Relayer 重启或重复处理同一事件时，不会导致重复铸造或释放
- **访问控制**：只有授权的 Relayer 地址可以调用 mint 和 release 函数
- **超时回滚机制**：
  - 每笔跨链交易设置超时时间（1 分钟）
  - 如果在超时时间内 Relayer 未能完成跨链操作（mint 或 release），原链上的资产应支持回滚
  - Lock 操作超时后，用户可调用 `refund` 函数取回锁定的 USDC
  - Burn 操作超时后，用户可调用 `refundBurn` 函数重新铸造被销毁的 USDC
  - 回滚操作只能由原交易发起人执行，且只能在超时后执行
  - 一旦跨链操作完成（已 mint 或已 release），回滚操作应被禁止
  - 合约需记录每笔交易的时间戳和状态（pending、completed、refunded）
  - 回滚成功后发出 `Refunded` 事件，包含 nonce、用户地址、退款金额

**5. Relayer 服务验收**
- Relayer 能够成功连接到 Hardhat 本地节点（http://localhost:8545）
- Relayer 能够成功连接到 solana-test-validator（http://localhost:8899）
- Relayer 能够持续监听两条链上的桥接合约/程序事件
- Relayer 检测到事件后，能够自动构造并提交跨链交易
- Relayer 日志清晰记录每笔跨链交易的处理状态（监听到、处理中、已完成、失败）
- Relayer 支持通过配置文件设置 RPC 端点、合约/程序地址、私钥等参数

**6. CLI 演示脚本验收**
- 提供 CLI 脚本，能够演示完整的 EVM → Solana 转账流程
- 提供 CLI 脚本，能够演示完整的 Solana → EVM 转账流程
- 脚本执行后，输出包含：
  - 转账前余额（两条链）
  - 交易哈希/签名
  - 事件日志
  - 跨链执行确认
  - 转账后余额（两条链）
- 余额变化与转账金额一致
- 脚本能够正确处理 EVM 地址和 Solana 公钥之间的转换

**7. 日志与可追溯性验收**
- Relayer 日志包含时间戳、事件类型、交易哈希、nonce、金额、用户地址
- 所有跨链交易可以通过 nonce 在两条链上关联查询
- 异常情况（如交易失败）有明确的错误日志和状态记录

**8. 超时回滚流程验收**
- **Lock 超时回滚场景**（EVM 侧）：
  - 用户在 Hardhat 本地链上锁定 MockUSDC，但 Relayer 在超时时间内未完成 mint 操作
  - 超时后用户调用 `refund` 函数成功取回锁定的 MockUSDC
  - 合约发出 `Refunded` 事件
  - 用户 MockUSDC 余额恢复到锁定前状态
  - 该 nonce 状态标记为 `refunded`，后续不能再被 Relayer 用于 mint
- **Burn 超时回滚场景**（Solana 侧）：
  - 用户在 Solana 测试验证器上销毁 SPL Token，但 Relayer 在超时时间内未完成 release 操作
  - 超时后用户调用 `refund_burn` 指令成功重新获得销毁的 SPL Token
  - 程序发出 `Refunded` 事件
  - 用户在 Solana 的 SPL Token 余额恢复到销毁前状态
  - 该 nonce 状态标记为 `refunded`，后续不能再被 Relayer 用于 release
- **防止双重支付**：
  - 如果 Relayer 在用户回滚前完成了跨链操作，用户的回滚操作应失败
  - 如果用户已回滚，Relayer 尝试执行 mint/release 应失败
  - 查询交易状态接口应能明确返回：pending、completed、refunded 三种状态

### 性能与边界条件
- 单笔跨链转账在正常网络条件下应在 5 分钟内完成（取决于链的出块时间）
- 跨链交易超时时间设置为 1 分钟（可配置）
- 合约应能处理最小转账金额（如 0.01 USDC）
- 合约应能处理的最大金额受合约锁定总额限制（需在合约中设置）
- Relayer 应能处理事件积压，按顺序处理历史未处理事件
- 回滚操作只能在超时后执行，确保给予 Relayer 足够的处理时间
